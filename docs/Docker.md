# Docker deployment

The shipped [Compose file](../docker-compose.yaml) runs one foreground `tt-sync serve` process. The image entrypoint selects `/state` for runtime state and `/state/config.toml` for configuration. The default workspace mount is `/data`.

## Start an instance

Prepare the files:

```bash
cp .env.example .env
mkdir -p .tt-sync/state
cp config.toml.example .tt-sync/state/config.toml
```

Edit [.env](../.env.example) for the host data directory, published port, and state location. Edit [config.toml](../config.toml.example) for the data layout and client-facing HTTPS address. Configuration paths refer to locations inside the container.

```bash
docker compose pull
docker compose up -d
docker compose run --rm tt-sync doctor
docker compose run --rm tt-sync pair open --json
```

The server and management commands share `/state`, so a pairing link generated by a separate command works with the running server. Keep that volume when replacing or upgrading the container.

## Certificates and reverse proxies

For external certificates, add a read-only certificate-directory mount and set the two `[tls]` paths to their container locations. See [TLS configuration](./CLI.md#tls-certificates-and-public-pins) for pin selection and renewal.

A reverse proxy connects to TT-Sync over HTTPS with TLS 1.3 and verifies the origin certificate. Set `public_url` and, when needed, `public_spki_sha256` for the public HTTPS endpoint. Preserve the `/v2/...` routes. The proxy or CDN that terminates public TLS becomes part of the trusted data path.

Image construction is defined by [Dockerfile](../Dockerfile); publishing is handled by the [release workflows](./README.md#release).
